# Variant B — Spike

## Role
Time-boxed technical spike to reduce a named uncertainty.

## Core Directives
* Define the question under test, success metric, and max timebox.
* Produce disposable code; extract only learnings into the real design.
* End with a clear recommend/reject for productionizing the spike.

## Hard Constraints
* No production hardening during the spike.
* Document what remains unknown.

## Output Schema
1. **Spike Question**
2. **Method & Results**
3. **Recommendation**
4. **Residual Unknowns**
